Membangun prototype aplikasi semantic search yang terintegrasi dengan LLM, dengan mengubah knowledge base menjadi embedding, menyimpannya dalam vector database, melakukan retrieval berdasarkan semantic similarity, lalu menghasilkan jawaban menggunakan LLM berdasarkan hasil retrieval tersebut.

1. # **Deskripsi Assignment**

   # Pada assignment ini, peserta akan membangun prototype aplikasi berbasis semantic search dan LLM menggunakan knowledge base FAQ. Peserta akan mengubah setiap entri FAQ menjadi embedding, menyimpannya ke dalam vector database (FAISS), mengimplementasikan fungsi semantic search, merancang prompt yang menyisipkan hasil retrieval sebagai context, kemudian mengintegrasikannya dengan LLM untuk menghasilkan jawaban. Assignment ini menjadi persiapan langsung sebelum peserta membangun RAG (Retrieval-Augmented Generation) system secara penuh pada sesi berikutnya.

2. # **Tujuan Assignment**

* Memahami alur end-to-end aplikasi berbasis semantic search: dari knowledge base hingga LLM-powered response.  
* Mengubah data knowledge base menjadi embedding menggunakan Gemini Embeddings API.  
* Menyimpan dan mengelola embedding dalam vector database menggunakan FAISS.  
* Mengimplementasikan fungsi semantic search untuk mengambil informasi paling relevan terhadap query pengguna.  
* Merancang prompt terstruktur (Persona, Task, Context, Format) yang menyisipkan hasil retrieval sebagai context.  
* Mengintegrasikan hasil semantic search dengan LLM untuk menghasilkan jawaban yang relevan dan akurat.  
* Menguji dan menganalisis relevansi hasil retrieval serta kualitas response AI yang dihasilkan.


3. # **Studi Kasus**

   Sebuah tim customer service e-commerce menerima ratusan pertanyaan repetitif dari pelanggan setiap harinya seputar pemesanan, pengiriman, pembayaran, hingga pengembalian barang. Tim ingin membangun prototype asisten AI yang dapat menjawab pertanyaan pelanggan secara otomatis berdasarkan knowledge base FAQ yang sudah ada, sebelum sistem ini dikembangkan lebih lanjut menjadi RAG system yang lebih kompleks.  
     
   Sebagai AI Engineer, Anda diminta membangun prototype awal: sistem yang dapat mencari entri FAQ paling relevan terhadap pertanyaan pelanggan (meskipun pelanggan tidak menggunakan kata-kata yang persis sama dengan FAQ), lalu menyusun jawaban yang natural menggunakan LLM berdasarkan FAQ yang ditemukan.

2. ## **Memahami Problem Statement**. Baca kembali Studi Kasus pada bagian awal brief ini, kemudian tuliskan dalam README.md:

* ## Objective dari use case (apa yang ingin diselesaikan).

* ## Sumber dan struktur knowledge base yang digunakan.

* ## Batasan atau asumsi yang digunakan (misal: sistem hanya menjawab berdasarkan FAQ yang tersedia).

3. ## **Menyiapkan Knowledge Base**. Muat knowledge base menggunakan Pandas, kemudian:

* Periksa struktur data (jumlah entri, kategori, kolom yang tersedia).  
* Gabungkan question dan answer menjadi satu unit teks yang representatif per entri, sebagai unit yang akan di-retrieve.

4. **Membuat Embeddings**  
* Ubah setiap unit retrievable menjadi vektor menggunakan Gemini Embeddings API.  
* Verifikasi dimensi/shape embedding yang dihasilkan sebelum lanjut ke tahap penyimpanan.

5. # **Menyimpan Embeddings ke Vector Database**

* # Buat index FAISS dan simpan seluruh embedding ke dalamnya.

* # Verifikasi jumlah vektor yang berhasil tersimpan sesuai jumlah entri knowledge base.

6. # **Mengimplementasikan Semantic Search** 

* Buat fungsi yang menerima query pengguna, mengubahnya menjadi embedding, lalu mencari entri FAQ paling relevan di index FAISS.  
* Tampilkan hasil pencarian beserta similarity score/distance masing-masing.

7. # **Mendesain Prompt dan Context** 

* Susun prompt terstruktur (Persona, Task, Context, Format).  
* Sisipkan hasil semantic search sebagai bagian Context dalam prompt.  
* Pastikan prompt mengarahkan LLM untuk menjawab hanya berdasarkan context yang diberikan, dan memberi tahu pengguna apabila informasi tidak tersedia di knowledge base.

8. **Mengintegrasikan LLM**   
* Kirimkan prompt yang sudah disusun ke Gemini AI API.  
* Gabungkan fungsi semantic search dan pemanggilan LLM menjadi satu alur (query → retrieval → prompt → jawaban).

9. **Menguji Relevansi Hasil Retrieval dan Response AI.** Uji sistem dengan minimal 5 query berbeda, mencakup:  
* 1-2 query yang jelas ada jawabannya di knowledge base.  
* 1-2 query dengan kata/frasa berbeda dari FAQ asli (parafrase atau sinonim), untuk menguji kemampuan semantic search menangkap makna, bukan hanya kata kunci.  
* 1 query yang tidak memiliki jawaban di knowledge base, untuk menguji bagaimana sistem merespons ketidaktahuannya.  
  Analisis hasil pengujian: query mana yang retrieval-nya akurat, mana yang kurang relevan, dan bagaimana kualitas jawaban LLM pada tiap kasus.

10. **Membuat Dokumentasi**. Buat file README.md yang memuat:  
* Deskripsi singkat problem statement dan knowledge base.  
* Penjelasan alur sistem (ingest → embed → store → retrieve → generate).  
* Hasil pengujian query beserta analisis relevansi.  
* Keterbatasan sistem yang ditemukan.  
* Cara menjalankan notebook/script.

# 	**Alur Eksperimen**

| Tahap | Proses dalam Assignment |
| :---- | :---- |
| **Ingest** | Memuat knowledge base FAQ dan menyiapkannya sebagai unit-unit retrievable |
| **Embed** | Mengubah setiap unit retrievable menjadi vektor menggunakan Gemini Embeddings API |
| **Store** | Menyimpan seluruh embedding ke dalam vector database (FAISS) |
| **Retrieve** | Menjalankan semantic search untuk mengambil entri FAQ paling relevan terhadap query |
| **Generate** | Menyisipkan hasil retrieval sebagai context ke dalam prompt, lalu menghasilkan jawaban melalui LLM |
